# Background: A2A (Agent-to-Agent Protocol)

- Optional segment: explained, not practised today
- Covers the Microsoft module "Discover Azure AI Agents with A2A"
- Product details are version-sensitive; verify before use

## How agents find and call each other

1. Discover: agent A reads the agent card of agent B (skills and endpoint)
2. Send: agent A sends a task over the A2A protocol
3. Receive: agent B returns the result

| Term       | Meaning                                                              |
| ---------- | -------------------------------------------------------------------- |
| A2A        | open protocol for agents to discover and call other agents           |
| Agent card | description of an agent: what it can do and where it is reachable    |
| Executor   | the component that runs a received task on the agent's side          |

## When it is needed

- Agents are owned by different teams or organisations
- The calling side cannot see or change the called agent's internals
- Not needed for a single-project agent such as TravelDesk, where code-level handoff is enough

## Trade-off

| Aspect          | Handoff in the same project | A2A across owners                          |
| --------------- | --------------------------- | ------------------------------------------ |
| Control         | one team controls both      | each owner controls its own agent          |
| Setup           | low                         | high: cards, endpoints, authentication     |
| Trust           | same boundary               | explicit trust and approval per remote agent |

> **Rule of thumb:** Use a protocol once agents span owners; inside one project, keep the handoff simple.
